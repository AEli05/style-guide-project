# Правила Markdown

Часть этих правил проверяет markdownlint, поэтому при нарушении Pull Request не пройдет проверку.

## Заголовки

- В файле один заголовок первого уровня `#`, и это первая строка.
- Уровни не пропускаем: после `##` идет `###`, а не `####`.
- Вокруг заголовка пустые строки.

## Списки

- Маркированный список - через `-`.
- Нумерованный список - для шагов, где важен порядок.
- Элементы одного списка в одной грамматической форме.

## Код

- Блоки кода только с тройными обратными кавычками и с указанием языка: `sql`, `python`, `bash`.
- Короткие имена в тексте - в одинарных обратных кавычках.

## Ссылки и изображения

- Текст ссылки объясняет, куда она ведет: «[описание витрины конверсии](examples/datamart.md)», а не «по ссылке».
- Внутренние ссылки - относительные пути к `.md` файлам.
- Изображения лежат в `docs/img/`, у каждого есть альтернативный текст.

## Предупреждения

Для важных замечаний используем блоки MkDocs:

```markdown
!!! warning "Данные досчитываются"
    Данные за последние 3 дня могут измениться.
```
