# Доступность текста

Документ должен быть понятен всем читателям: тем, кто читает с телефона, пользуется экранным диктором, плохо различает цвета или просто открыл отчет между встречами.

## Структура

- Заголовки идут по порядку уровней. По ним ориентируются экранные дикторы и оглавление сайта.
- Важное - в начале: вывод в первом абзаце, ключевое слово в начале пункта списка.
- Длинный раздел разбиваем подзаголовками, примерно каждые 3-5 абзацев.

## Текст

- Предложения до 25 слов, абзацы до 5 предложений.
- Аббревиатуру расшифровываем при первом упоминании.
- Не пишем «см. выше» и «справа»: на телефоне или в дикторе этого «справа» нет. Даем ссылку на раздел.

## Цвет

- Смысл не передается только цветом. Плохо: «красные строки - упавшие метрики». Хорошо: столбец «Изменение» со знаком и словом «снижение».
- На графиках группы различаются не только цветом, но и подписями или типом линии.
- Текст на цветном фоне должен быть контрастным.

## Изображения

- У каждого изображения есть альтернативный текст: `![График конверсии по дням: тестовая группа выше весь период](img/conv.png)`.
- Альтернативный текст передает вывод графика, а не «график».
- Цифры, важные для вывода, дублируются в тексте или таблице.

## Таблицы

- У таблицы есть строка заголовков.
- Объединенные ячейки не используем.
- Таблицу не используем для верстки, только для данных.

## Ссылки

- Текст ссылки описывает цель: «[чек-лист перед публикацией](review.md)», а не «тут».
- Одна и та же цель - одинаковый текст ссылки во всем документе.
