# Назначение и аудитория

## Область применения

Руководство обязательно для всех документов аналитической команды, которые читает кто-то кроме автора:

- отчеты по A/B-тестам;
- описания SQL-витрин и регулярных запросов;
- описания дашбордов.

Черновики, личные заметки и рабочие ноутбуки под правила не попадают, пока их не отправили заказчику.

## Читатели

| Читатель | Что ему нужно | Что это значит для автора |
| --- | --- | --- |
| Продакт-менеджер, маркетолог | Понять, что делать дальше | Вывод и рекомендация в первом абзаце, без формул |
| Руководитель | Быстро оценить результат и риски | Короткое резюме, ключевые цифры, ограничения |
| Другой аналитик | Проверить и повторить расчет | Источники, SQL, период, фильтры, метод |
| Новый сотрудник | Разобраться в метриках и данных | Описания витрин и глоссарий |

Перед тем как писать, автор отвечает себе на два вопроса: кто главный читатель и какое решение он примет после прочтения. Если ответа нет, документ пока писать рано.

## Авторы

Документы пишут аналитики команды. Каждый документ имеет автора и ревьюера. Ревьюер - другой аналитик, который не участвовал в расчете.

## Инструменты

- Документы пишутся в Markdown и хранятся в git-репозитории.
- Сайт документации собирается MkDocs.
- Изменения проходят через Pull Request и автоматическую проверку (линтер и проверка стиля).
- Расчеты делаются в SQL и Python, код прикладывается к документу или хранится рядом.
