# Проверка и чек-лист

## Процесс ревью

1. Автор создает ветку и Pull Request.
2. Автоматическая проверка запускает markdownlint, проверку стиля и сборку сайта.
3. Ревьюер - аналитик, который не участвовал в расчете - проверяет документ по чек-листу и повторяет хотя бы один ключевой расчет.
4. Автор исправляет замечания или объясняет в комментарии, почему оставил как есть.
5. После одобрения ревьюера Pull Request сливается в `main`, сайт обновляется автоматически.

## Чек-лист перед публикацией

### Смысл

- [ ] Вывод и рекомендация в первом абзаце.
- [ ] Понятно, для кого документ и какое решение он помогает принять.
- [ ] Есть раздел «Ограничения».

### Цифры

- [ ] У каждой цифры есть период и единица.
- [ ] Указана дата выгрузки данных.
- [ ] Разница процентов в п.п., относительный эффект в %.
- [ ] Округление одинаковое для одинаковых величин.

### Статистика

- [ ] Указаны тест, α, размер групп, доверительный интервал, p-value.
- [ ] Нет слов «доказали» и «значимо» без теста.
- [ ] Корреляция не выдается за причинность.

### Оформление

- [ ] Метрики названы как в глоссарии.
- [ ] SQL оформлен по правилам и приложен.
- [ ] У графиков есть подписи, оси и источник.
- [ ] Нет персональных данных.
- [ ] Локальная проверка `python scripts/check_style.py` проходит без ошибок.
